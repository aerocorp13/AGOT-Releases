# Feedback, contributions and responsible collaboration

Thank you for evaluating AGOT Desktop. This repository contains **public release documents and installer metadata**; the AGOT desktop application source is maintained separately and is not open for public pull requests through this repository.

## Ways to help

- Report a reproducible bug in the current **published installer**.
- Suggest a missing GIS workflow or a real-world scenario use case.
- Improve clarity, accessibility, typo fixes and documentation via a small pull request to this distribution repo.
- Contribute permitted data examples, test procedures or feedback after coordinating license and privacy requirements.

## Before opening an issue

Check [FAQ](docs/FAQ.md), [Capabilities](docs/CAPABILITY_MATRIX.md), [Quality and limitations](docs/QUALITY_AND_LIMITATIONS.md) and the relevant [release](https://github.com/aerocorp13/AGOT-Releases/releases).

A good report contains:
- **AGOT version:** e.g. 1.0.2 Preview 3, MSI filename and Windows version.
- **Task:** Map, World, GeoAI, GIS processing, 3D, install or upgrade.
- **Input classification:** authorized public dataset, private data (do **not** attach), or test fixture; include CRS/format when useful.
- **Reproducible steps:** numbered instructions, expected result, actual result and sanitized logs.
- **Environment:** WebView2/runtime/model availability and whether online sources were enabled.

For feature proposals, state the planning decision/user need, input/output expectations, data ownership, authorization implications and whether the feature must operate offline.

**Please do not post secrets, company datasets, access tokens or personal information in public issues.** Report vulnerabilities privately via [SECURITY.md](SECURITY.md). There is no promised public feature acceptance or response-time SLA.

## Claims and governance

Documentation PRs should identify whether a statement describes a **published release**, a **tested development implementation**, a **prototype**, or a **planned milestone**. Include the actual release/validation evidence; do not add fake achievements, badges, usage statistics, benchmarks or unverified screenshots.

**Licensing:** repository documentation under MIT is separate from AGOT installer/software licensing and third-party notices.
